# Contributing

Thank you for helping make junior developer opportunities easier to find.

## Before making changes

1. Read the inclusion criteria in README.md.
2. Check whether the opportunity is already listed.
3. Check open pull requests to avoid duplicate work.
4. Open the official listing and verify the details.

Do not add invented opportunities, referral promotions, or listings that require applicants to pay an application fee.

## Adding an opportunity

Add one row to the opportunities table in README.md.

Include:

- Company name
- Exact role title
- Location and work arrangement as stated
- Required experience
- Relevant skills from the listing
- Direct official job listing URL
- Last-checked date in YYYY-MM-DD format

Use "Not specified" for missing requirements. Do not assume that "remote" means applicants from every country are eligible.

Keep entries alphabetical by company name. Use the role title to order multiple entries from the same company.

Write short factual summaries rather than copying full job descriptions. Do not include personal information about applicants or recruiters.

Check graduation-year requirements separately from work experience. Exclude student-only internships and listings restricted to specific graduation batches or recent graduates. If graduation year or career-gap eligibility is not stated, record "Not specified"; do not infer acceptance.

## Updating or removing an opportunity

Explain what changed and include the official source.

If a link fails temporarily, report it for review rather than assuming the role is closed.

## Pull requests

- Create a branch for your change.
- Keep changes focused.
- Review your diff before committing.
- Describe what changed and how you checked it.
- Follow any pull request template provided by the project.

## Using AI tools

AI can help explain the workflow or review a draft, but contributors must personally verify listing details and understand their changes. Do not submit AI-generated claims without checking the official source.
